# Startauftrag an Codex

Du bist der Orchestrator gemaess AGENTS.md. Lies docs/project-idea.md und docs/tech-stack.md. Beginne mit Requirements, Validierung, Architektur und einem priorisierten Task-Backlog. Backlog-IDs: `FEAT` fuer Faehigkeiten aus der Projektidee, `TECH` fuer Scaffolding, Infrastruktur und CONTRACT_CHANGEs. Klassifiziere relevante Aufgaben zusaetzlich als CURRENT_STACK_ONLY, TARGET_ALIGNED oder REQUIRES_MIGRATION. Zeige mir kritische offene Fragen und empfohlene Stack-Abweichungen, bevor du irreversible Architekturentscheidungen triffst. Implementiere anschliessend inkrementell lokal, delegiere an passende Subagents und pruefe jeden Task mit Code Review und Tests. Beginne mit `scripts/sync-main.mjs` (main auf Remote-Stand, falls Remote). Jede Anfrage startet mit der Klaerungsphase (Rueckfragen an mich). Tasks via `scripts/add-task.mjs` anlegen, Status via `scripts/update-task.mjs`, Task-Branches via `scripts/branch-task.mjs` (Name = Task-ID), rote Tests zuerst via `scripts/record-check.mjs`, Merge via `scripts/merge-task.mjs` nach Review. Jede umgesetzte nutzerpruefbare Faehigkeit wird in tasks/inventory.json dokumentiert (Pflicht vor DONE). Nutze maximal drei parallele Subagents. Dokumentiere echte Testergebnisse und Blocker. Fuehre kein Deployment durch; Push nur Task-Branches bei Remote (`scripts/push-task.mjs`). Stoppe bei sicherheitskritischen Freigaben, unklaren Produktentscheidungen oder ausstehenden Stackentscheidungen.
