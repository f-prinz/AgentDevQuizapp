# Playbook: Question

Reine Verstaendnis-/Recherchefrage. Kein Code wird geaendert.

## Ablauf
1. **Read-only arbeiten.** Keine Dateiaenderungen, keine Backlog-Eintraege, kein Statuswechsel.
2. **Frage eingrenzen.** Bei Mehrdeutigkeit eine fokussierte Rueckfrage stellen statt zu raten (Vollformat fuer den Nutzer: `docs/templates/request-question.md`).
3. **Evidenz sammeln:** zuerst docs/ (requirements, architecture, data-model, docs/tech-stack.md, final-report), dann Code und tasks/state.json. Antwort mit Datei- und Zeilenreferenzen belegen.
4. **Antworten:** direkte Antwort zuerst, dann Details. Behauptungen nur aus gelesenem Code/Docs, nicht aus Annahmen. Bei Technologiefragen aktuellen Stack und freigegebene Zielarchitektur trennen.
5. **Optional:** Falls die Antwort einen Folge-Task nahelegt, diesen als Vorschlag formulieren – nicht anlegen, ausser der Nutzer bestaetigt.

## Ergebnisformat
Antwort | Referenzen (Datei:Zeile) | offene Unsicherheit | optionaler Folge-Vorschlag
